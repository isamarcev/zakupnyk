# Zakupnyk

**Облік закупівель без хаосу: потреба → рахунки → оплати → документи.**

Інструмент для тих, хто веде закупівлі: формуєш перелік потреби, збираєш ціни від різних постачальників, відстежуєш кожну позицію за стадіями (рахунок → оплата → поставка → закриття) і тримаєш усі рахунки та накладні прив'язаними до конкретних позицій — замість розрізнених Excel-файлів і папок.

## Можливості

- **Закупівлі** — проєкти зі статусами, кошторисом і прогресом виконання.
- **Позиції з кольоровими стадіями** — Нове → Очікую рахунок → Передано на оплату → Оплачено → Отримано → Закрито (+ Проблема). Зміна стадії одним кліком, фільтри по стадіях.
- **Пропозиції постачальників** — ціни та посилання (Prom.ua, Rozetka, дистриб'ютори) для кожної позиції; нового постачальника можна створити прямо з форми.
- **Замовлення** — позиції, які купуються одним рахунком в одного продавця, збираються в групу: галочки в таблиці → «Нове замовлення». Стадія і рахунок ставляться на всю групу одразу, а не по разу на позицію. Замовлення — окрема вісь від модулів: перемикач «Групувати: 🧩 Модулі / 📦 Замовлення», фільтр `?order=`.
- **Експорт документів у ZIP** — вибираєте тип (Рахунок, Накладна, Договір, Інше або всі) і тиснете «⬇️ Експорт»: архів збирається по тому, що зараз відфільтровано (стадії, конкретне замовлення або вибрані галочками позиції). Усередині — плоский список файлів і `_перелік.txt` зі специфікацією позицій (групи нумеруються «Група 1», «Група 2» — так само, як згруповано на сторінці).
- **Документи по позиціях** — рахунок/накладна вантажиться до конкретної позиції (у кожної може бути свій постачальник); файли лежать звичайною папковою структурою `data/files/<закупівля>/<постачальник>/`, видні у провіднику.
- **Платники** — реквізити фондів/осіб: вставте блок тексту як є — ім'я, IBAN та ЄДРПОУ розпізнаються автоматично; копіювання реквізитів одним кліком.
- **Імпорт з Excel** — кожен лист переліку потреби стає закупівлею, ціни по колонках — пропозиціями постачальників.
- **Пошук** — по документах, постачальниках, платниках, історії.

## Швидкий старт

```bash
make setup      # uv sync — створити .venv і поставити залежності (потрібен uv)
make run        # запустити; відкриється http://127.0.0.1:8077
```

### Docker

```bash
make docker-up     # зібрати і запустити у фоні → http://localhost:8077
make docker-logs   # подивитися логи
make docker-down   # зупинити
```

Дані (`./data`) монтуються з хоста і переживають перезбірку.
Інший порт: `PROCFLOW_PUBLIC_PORT=9000 make docker-up`.

### Імпорт переліку потреби

```bash
make import-xlsx file="шлях/до/перелік.xlsx"
```

або через сторінку «Імпорт» у додатку. Очікувані колонки: A — найменування, C — потреба, D — придбано/замовлено, E — в роботі, F — ціна, I — специфікація, J–K — Prom.ua, L–M — Rozetka, N–O — дистриб'ютор.

## Дані та бекап

| Що | Де |
|---|---|
| База | `data/procflow.db` (SQLite) |
| Файли документів | `data/files/<закупівля>/<постачальник>/` |
| Налаштування | `.env` (див. `.env.example`) |

Бекап = скопіювати папку `data/`. Жодних зовнішніх сервісів, все локально.

## Архітектура

Шарувата архітектура (clean architecture). Кодова назва пакета — `procflow`:

```
src/procflow/
├── domain/          # сутності, доменні помилки — без зовнішніх залежностей
├── application/     # use-cases (commands/queries), інтерфейси (Protocol), DTO, UnitOfWork
├── infrastructure/  # SQLAlchemy-репозиторії, файлове сховище, парсер Excel
├── presentation/    # FastAPI-роутери + Jinja2-шаблони
└── main/            # конфіг, DI-контейнер, app factory, CLI імпорту
```

Правило залежностей: `presentation → application ← infrastructure`, `domain` не залежить ні від чого. Схема БД створюється автоматично; нові колонки докочуються ідемпотентними мініміграціями при старті.
